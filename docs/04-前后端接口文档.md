## 1. 通用规范

基地址：`https://{host}/api/v1`；版本以路径维护。受保护接口头部为 `Authorization: Bearer {accessToken}`，JSON 请求使用 `Content-Type: application/json`。时间为 ISO 8601 UTC，如 `2026-07-11T08:00:00.000Z`；分页参数 `page`（从1开始）和 `pageSize`（默认20、最大100）。上传使用 `multipart/form-data`，字段为 `file` 和可选 `name`。

成功响应统一为：

```json
{"code":"OK","message":"success","data":{},"requestId":"req_01H..."}
```

失败响应统一为：

```json
{"code":"AUTH_TOKEN_INVALID","message":"登录凭证无效或已过期","data":null,"requestId":"req_01H..."}
```

所有字段使用 lowerCamelCase；错误码见《07-错误码说明》。`POST /reviews` 必须额外携带 `Idempotency-Key` 请求头；同一键配合相同 `contractId`、`contractFileId`、`reviewMode` 与 `sourceWarningId`（为空时也纳入比较）返回同一审核记录，不同载荷返回 `IDEMPOTENCY_CONFLICT`。

### M3.3 预警接口状态与数据权限

`risk_rule.warningEnabled` 与 `warningDueHours` 由既有管理员风险规则接口配置；规则配置只影响后续审核，不能在审核前为具体合同创建预警。AI 初审风险和规则快照成功落库后，业务后端按稳定 `warningKey` 幂等创建 `pendingLegal` 候选预警。候选预警的 `sourceSnapshot` 是不可变 AI 证据，仅法务、风控在其授权范围内可读取；普通用户从不将其作为正式预警结果查看。管理员仅通过 Dashboard 和操作日志读取预警统计与审计信息，不通过预警详情读取具体原始快照。面向普通用户的 `active`/`processing` 预警必须返回经人工核验的 `effectiveRisk` 摘要。

既有 `riskStatus` 仍只表示 `risk_record` 在人工修订后的风险记录状态，不能代替也不能驱动 `warningStatus`；一个风险可被 `dismissed` 而候选预警由法务撤回为 `withdrawn`，两类历史均须保留。普通用户不得通过任何预警接口直接创建、修改、撤销、豁免或关闭预警。

| 接口 | 前置状态与角色 | 请求字段 | 状态迁移与留痕 | 数据权限 |
|---|---|---|---|---|
| `POST /reviews`（带`sourceWarningId`） | 普通用户为预警`ownerId`，预警为`active`，新文件属于同一合同 | `contractId,contractFileId,reviewMode,sourceWarningId` | 创建整改复审并将预警置`processing`，写入`remediationReviewId`和`remediationStarted`动作；复审失败/取消时恢复`active`并保留`dueAt` | 用户不能借此关联他人预警、不同合同或非`active`预警 |
| `POST /warnings/{warningId}/legal-confirm` | 法务审核员；来源审核为`processing/legalReview`；预警为`pendingLegal` | `comment?` | `pendingLegal -> pendingRisk`并写`legalConfirmed` | 仅法务候选待办 |
| `POST /warnings/{warningId}/legal-withdraw` | 法务审核员；来源审核为`processing/legalReview`；预警为`pendingLegal` | `comment`（必填） | `pendingLegal -> withdrawn`并写`withdrawn` | `withdrawn`后不再对普通用户可见 |
| `POST /warnings/{warningId}/risk-activate` | 风控审核员；来源审核为`processing/riskReview`；预警为`pendingRisk` | `dueAt?,comment?` | `pendingRisk -> active`，可设置`dueAt`并写`remediationRequired` | 仅风控待办；管理员不得代办 |
| `POST /warnings/{warningId}/waive` | 风控审核员；预警为`pendingRisk`或`active` | `comment`（必填） | `pendingRisk|active -> waived`并写`waived` | 管理员不得代办 |

| `POST /warnings/{warningId}/reopen` | 风控审核员；预警为`closed`或关联整改复审完成的`processing` | `comment?,dueAt?` | `closed|processing -> active`并写`reopened` | `processing`关联复审不正确时返回`WARNING_REMEDIATION_REVIEW_INVALID` |

`overdue` 不提供独立写接口，也不是 `warningStatus` 枚举值。列表、详情和 Dashboard 在 `warningStatus in (active,processing)` 且 `dueAt` 已超过当前 UTC 时间时返回 `overdue=true`；读取或扫描不得把状态改写为“逾期”。M3.3 首版仅设计站内预警中心、审核员待办和 Dashboard 的 `warningsByStatus`、`overdueWarnings` 聚合，短信、邮件、企业微信和钉钉通知均不在本接口范围内。

## 3. 关键报文示例

登录请求与响应：

```json
{"username":"demo","password":"***"}
```

```json
{"code":"OK","message":"success","data":{"accessToken":"<jwt>","tokenType":"Bearer","expiresIn":3600,"user":{"id":1,"username":"demo","role":"user","userStatus":"active"}},"requestId":"req_x"}
```

发起审核请求：

```json
{"contractId":1001,"contractFileId":2001,"reviewMode":"full","sourceWarningId":null}
```

审核结果响应的 `data` 与《05-AI服务接口文档》的完整结果结构保持一致，并额外包含 `reviewId`、`reviewStatus`、`reviewStage`、`aiResult`（不可变AI初审结果）、`legalReview`、`riskReview` 和 `effectiveResult`（由AI初审与人工修订计算的当前有效结果）。`aiResult` 在 `reviewStage=legalReview` 起可读取，`REVIEW_RESULT_NOT_READY` 仅表示 AI 初审尚不可用。`legalReview` 至少包含 `reviewerId,reviewedAt,opinion,revisions`，`riskReview` 至少包含 `reviewerId,reviewedAt,opinion,revisions,overallRiskLevel,overallScore`。风险对象必须包含 `riskType`、`riskName`、`riskLevel`、`clauseText`、`page`、`paragraphIndex`、`basis`、`suggestion`、`confidence`、`ruleId`（整数，可空）。所有 PATCH 仅追加修订记录，禁止覆盖AI初审行；普通用户对审核结果只有查看权限。

## 4. 前端约定

Axios 响应拦截器统一处理 `code`；401 清理本地登录态并跳转登录页，403 展示无权限。前端不得拼接存储路径、直连 AI 服务或 Qwen API。长任务采用轮询进度接口，

轮询间隔：2秒
AI轮询停止条件：`reviewStage` 不再为 `aiReview`，或 `reviewStatus` 为 `failed`、`cancelled`
最长自动轮询：5分钟
超过5分钟：停止自动轮询，提示用户手动刷新。

## M2.2 实现补充（2026-07-13）

人工复核接口均接入 `/api/v1`。法务仅能写 `processing/legalReview`，其中既有风险仅能修订`riskLevel`、`suggestion`和`comment`，不能提交`riskStatus`；风控仅能写 `processing/riskReview`，可修订风险状态与总体风险。管理员与普通用户没有人工复核写权限。首次写操作在同一事务自动领取，已由他人领取时返回 `REVIEW_ALREADY_CLAIMED`。

`effectiveResult` 从不可变 `aiResult` 的深拷贝开始，按 `createdAt,id` 升序叠加 `review_revision`；要素和风险分别返回数据库生成的 `elementId`、`riskId`，`dismissed` 风险仍保留。确认迁移为 `processing/legalReview -> processing/riskReview -> completed/completed`，最终确认同时将合同置为 `reviewed` 并创建唯一的 `pending/html` 报告记录，但不生成文件。

## M3.1 管理后台与 Dashboard 实现补充（2026-07-13）

M3.1 使用本表既有非 `/admin` 路径，不创建同义接口。所有接口均需 JWT 且仅 `admin` 可访问；管理员仍不能调用法务/风控修订、反馈或确认接口。用户管理实现管理员创建、查询和更新，不提供公开注册、密码重置或找回密码；创建用户默认启用且密码仅以哈希形式存储；管理员不能将自己降级或停用。所有列表使用 `page`、`pageSize`（最大100），并按 `createdAt DESC,id DESC` 稳定排序。

标准条款与风险规则的 DELETE 为 `configStatus=disabled` 停用，不物理删除；创建、修改、停用以及用户更新与操作日志在同一事务提交。配置变更只影响后续审核，不更新历史 `ruleSnapshot`、`aiResult` 或人工修订记录。管理员反馈与操作日志接口只读；操作日志响应统一脱敏密码、令牌、密钥和内部路径字段。

Dashboard 返回 `contractsTotal`、`contractsByStatus`、`reviewsTotal`、`reviewsByStatus`、`reviewsByStage`、`effectiveRisksByLevel`、`pendingLegalReview`、`pendingRiskReview`、`completedReviews` 与 `contractUploadTrend`。合同和关联审核统计排除逻辑删除合同；未提供时间范围时总量为全量、趋势为最近7个UTC自然日，提供单边时间时补齐为不超过366天的窗口。风险分布统计所有已存在AI快照的审核，不限于 completed；批量读取 `risk_record` 与 `review_revision`，按 `created_at ASC,id ASC` 叠加风险修订，以最终 `riskLevel` 计数，最终 `riskStatus=dismissed` 的风险不计入分布。该口径与审核详情的 `effectiveResult` 一致。

M3.2 的 HTML/PDF 文件生成、报告任务、重试和下载仍未实现；M2.2 创建的唯一 `pending/html` 占位记录不会在 M3.1 被消费。

## M3.2 报告生成与下载（2026-07-13）

报告统一基于审核详情的 `effectiveResult` 构建；合同类型、要素、总体风险和风险列表均应用全部人工修订。最终状态为 `dismissed` 的风险不进入当前有效风险列表和等级汇总，只显示已忽略数量。HTML 使用自动转义模板和内嵌样式，PDF 使用同一结构化上下文直接排版。

报告状态为 `pending -> generating -> completed`，失败转为 `failed`。数据库执行器原子领取 pending 或超过失活阈值的 generating 任务，最多尝试 `REPORT_MAX_ATTEMPTS` 次。文件在受控目录临时写入、原子替换成功后才提交 completed；数据库完成更新失败时删除已发布文件。retry 只允许管理员将未超过次数上限的 failed 记录恢复为 pending。

下载前同时校验审核数据权限、completed 状态、相对路径边界、普通文件存在性和文件大小。HTML 使用 `text/html; charset=utf-8`，PDF 使用 `application/pdf`；响应不包含服务器绝对路径。

## 交付前 OpenAPI 一致性补充（2026-07-13）

FastAPI OpenAPI 中所有外部 path 参数统一使用 lowerCamelCase（如 `contractId`、`reviewId`、`elementId`、`riskId`、`reportId`），与本文件一致；内部 Python 参数继续使用 snake_case。除 `/health` 与 `/api/v1/auth/login` 外，所有业务接口均声明 Bearer 鉴权。`reviewMode`、`reportFormat`、角色、合同类型、风险类型、风险等级和配置状态均在请求 Schema 中暴露枚举约束，不保留同义字段或同义接口。

OpenAPI、Swagger UI 和 ReDoc 可通过 `OPENAPI_ENABLED` 控制；生产环境默认关闭。运行时成功/失败响应仍严格使用本文件第1节统一包装，文件下载接口按实际文件格式返回流式响应。
