## 1. 通用规范

基地址：`https://{host}/api/v1`；版本以路径维护。受保护接口头部为 `Authorization: Bearer {accessToken}`，JSON 请求使用 `Content-Type: application/json`。时间为 ISO 8601 UTC，如 `2026-07-11T08:00:00.000Z`；分页参数 `page`（从1开始）和 `pageSize`（默认20、最大100）。上传使用 `multipart/form-data`，字段为 `file` 和可选 `name`。

成功响应统一为：

```json
{"code":"OK","message":"success","data":{},"requestId":"req_01H..."}
```

失败响应统一为：

```json
{"code":"AUTH_TOKEN_INVALID","message":"登录凭证无效或已过期","data":null,"requestId":"req_01H..."}
```

所有字段使用 lowerCamelCase；错误码见《07-错误码说明》。

## 3. 关键报文示例

登录请求与响应：

```json
{"username":"demo","password":"***"}
```

```json
{"code":"OK","message":"success","data":{"accessToken":"<jwt>","tokenType":"Bearer","expiresIn":3600,"user":{"id":1,"username":"demo","role":"user","userStatus":"active"}},"requestId":"req_x"}
```

发起审核请求：

```json
{"contractId":1001,"reviewMode":"full"}
```

审核结果响应的 `data` 与《05-AI服务接口文档》的完整结果结构保持一致，并额外包含 `reviewId`、`reviewStatus` 和用户修订后的字段。风险对象必须包含 `riskType`、`riskName`、`riskLevel`、`clauseText`、`page`、`paragraphIndex`、`basis`、`suggestion`、`confidence`、`ruleId`（整数，可空）；要素修订接口以 `value` 写回 `contract_element.value_text`，并以 `source=user` 和反馈记录留痕。

## 4. 前端约定

Axios 响应拦截器统一处理 `code`；401 清理本地登录态并跳转登录页，403 展示无权限。前端不得拼接存储路径、直连 AI 服务或 Qwen API。长任务采用轮询进度接口，

轮询间隔：2秒
停止状态：completed、failed、cancelled
最长自动轮询：5分钟
超过5分钟：停止自动轮询，提示用户手动刷新。
