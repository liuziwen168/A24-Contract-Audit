## 1. 命名与格式规范

外部 JSON 全部为 lowerCamelCase；Python 内部可使用 snake_case，并通过 Pydantic alias 转换。数据库表/列为 snake_case。日期使用 `YYYY-MM-DD`，时间使用 ISO 8601 UTC（`YYYY-MM-DDTHH:mm:ss.SSSZ`）；金额使用十进制字符串或 `decimal(18,2)`，单位人民币元，禁止浮点金额。置信度范围 `[0,1]`，风险总分范围 `[0,100]`。

### 2.1 审核状态机

`reviewStatus` 表示整份合同审核的生命周期，`reviewStage` 表示当前可执行的业务阶段；二者必须同时返回、同时持久化，且不得用 `reviewStatus=completed` 表示“仅 AI 初审完成”。状态组合仅允许如下取值：

| `reviewStatus` | `reviewStage` | 含义与可执行操作 |
|---|---|---|
| `pending` | `aiReview` | 已创建、待任务执行器领取 |
| `processing` | `aiReview` | AI 正在解析或审核 |
| `processing` | `legalReview` | AI 初审已保存，法务审核员可复核；AI结果可读取 |
| `processing` | `riskReview` | 法务已确认，风控审核员可复核；AI与法务结果可读取 |
| `completed` | `completed` | 风控已确认，最终结果与报告可读取 |
| `failed` | `aiReview` | AI 初审失败，可由合同所有人重新发起新的审核 |
| `cancelled` | `aiReview` | AI 初审开始前已取消 |

状态迁移固定为：`pending/aiReview → processing/aiReview → processing/legalReview → processing/riskReview → completed/completed`；AI失败转为 `failed/aiReview`，仅 AI 初审开始前允许转为 `cancelled/aiReview`。`contractStatus` 随之为 `uploaded → reviewing → reviewed`；AI失败时为 `failed`。重新上传或重新审核必须创建新的文件版本和新的审核记录。

### 2.2 预警状态机（M3.3 设计待开发）

`warningStatus` 描述某一命中风险的处置闭环，和同一来源审核的 `reviewStatus`/`reviewStage` 分开存储、同时校验。预警规则只是在审核前由管理员配置触发条件；具体候选预警只能在 AI 初审结果与风险记录成功落库后创建。

| `warningStatus` | 可见性与允许操作 | 合法进入与离开 |
|---|---|---|
| `pendingLegal` | 仅法务审核员；来源审核须为`processing/legalReview` | 命中启用预警规则后由系统幂等创建；法务核验后转`pendingRisk`或`withdrawn` |
| `pendingRisk` | 仅风控审核员；来源审核须为`processing/riskReview` | 法务确认有效后进入；风控处置后转`active`或`waived` |
| `active` | 仅合同所有人可查看、知悉并发起整改复审；风控可跟踪 | 风控要求整改并设置`dueAt`后进入；经办人发起整改复审转`processing`，或风控重开后回到此状态 |
| `processing` | 合同所有人可查看关联整改复审；风控等待并核验复审结果 | 经办人以`sourceWarningId`发起整改复审后进入；风控在复审完成后转`closed`或`active`，复审失败/取消时回到`active` |
| `closed` | 仅风控可重开；风控关闭时间写入`closedAt` | 风控确认关联整改复审已完成且风险消除后进入，或对`active`预警直接关闭 |
| `withdrawn` | 仅审计/管理读取；普通用户不可见 | 法务确认候选预警误报或不适用后进入终态 |
| `waived` | 仅审计/管理读取；普通用户不可见 | 风控书面接受风险、不要求整改后进入终态 |

`overdue` 是 API 和 Dashboard 的派生布尔字段，不能写入 `warningStatus`：仅当 `warningStatus` 为 `active` 或 `processing` 且非空 `dueAt` 已早于当前 UTC 时间时为 `true`。读取、扫描和展示 `overdue` 不改变任何预警状态，也不产生外部通知。

## 3. 风险类型（不少于10类）

| `riskType` | 风险名称 | 默认等级建议 |
|---|---|---|
| `unlimitedLiability` | 无限责任 | high |
| `excessiveLiquidatedDamages` | 违约金过高 | high |
| `unilateralTermination` | 单方解除权 | high |
| `unfairPaymentTerms` | 不合理付款条件 | medium |
| `unfavorableJurisdiction` | 管辖/争议解决不利 | medium |
| `missingDisputeResolution` | 缺失争议解决条款 | medium |
| `overbroadConfidentiality` | 保密义务过宽 | medium |
| `missingConfidentiality` | 缺失保密条款 | medium |
| `missingPerformanceTerm` | 缺失履行期限 | medium |
| `ambiguousAcceptance` | 验收标准不明确 | medium |
| `intellectualPropertyUnclear` | 知识产权归属不清 | medium |
| `forceMajeureMissing` | 缺失不可抗力条款 | low |

默认等级仅为规则初值；审核输出等级以规则和人工复核为准。

## 4. 要素与核心字段

| `elementType` | `elementName` | 值格式 |
|---|---|---|
| `partyA` | 合同甲方 | 文本 |
| `partyB` | 合同乙方 | 文本 |
| `signingDate` | 签署日期 | `YYYY-MM-DD` 或原文文本 |
| `contractAmount` | 合同金额 | 数字字符串，元 |
| `performanceTerm` | 履行期限 | 文本或标准日期区间 |
| `disputeResolution` | 争议解决方式 | 文本 |

关键外部字段：`requestId`（字符串，调用追踪）、`contractId`/`contractFileId`/`reviewId`/`riskId`/`ruleId`/`warningId`/`remediationReviewId`（整数ID，`ruleId`可空）、`typeConfidence`/`confidence`（0至1）、`page`（从1开始的整数，可空）、`paragraphIndex`（从0开始的整数，可空）、`processingTimeMs`（非负整数）、`missingClauses`（条款类型字符串数组）、`warnings`（AI解析/结构化告警字符串数组，不是业务预警）、`error`（对象或 null）。预警对象使用 `warningKey`、`reviewId`、`contractId`、`warningStatus`、`dueAt`、`overdue`、`acknowledgedAt`、`closedAt`；`sourceSnapshot` 仅在法务、风控授权范围内返回，普通用户只读取基于人工核验的风险摘要，管理员只读取预警统计和操作日志。`warningEnabled` 为布尔值，`warningDueHours` 为可空正整数。审核资源必须返回 `reviewStatus` 与 `reviewStage`；`reviewStatus=processing` 且 `reviewStage` 为 `legalReview` 或 `riskReview` 时，`aiResult` 已可读取。数据库 `status` 字段在外部 JSON 中按资源类型映射为 `userStatus`、`contractStatus`、`reviewStatus`、`riskStatus`、`warningStatus`、`reportStatus` 或 `configStatus`，不得使用无上下文的 `status` 作为业务契约字段。

## 5. 变更控制

新增枚举不得复用既有值；废弃值先在字典标记并保留兼容读取。字典变更必须同时更新数据库校验、Pydantic schema、前端显示映射、接口文档和错误码说明，并记录在《09-开发进度与分工记录》。

## M2.2 人工复核枚举补充（2026-07-13）

- `review_revision.target_type`：`contractType`、`element`、`risk`、`overallRisk`。
- `riskStatus`：`active`、`modified`、`dismissed`。
- `review_feedback.judgment`：`correct`、`incorrect`、`modified`。
- `review_revision.actor_role`：`legalReviewer`、`riskReviewer`。
- 人工修订的 `overallScore` 按 Decimal 校验并以 JSON 安全的十进制字符串持久化，禁止经由 float 计算。

## M3.2 报告字段补充（2026-07-13）

- `reportFormat`：仅 `html`、`pdf`。
- `reportStatus`：`pending -> generating -> completed`；生成异常转为 `failed`。
- `attemptCount`：非负整数，领取或失活恢复时加一。
- `storagePath` 为内部相对路径，不出现在 API 响应中；外部仅返回 `fileSize`、`sha256`、`generatedAt` 和安全 `errorCode`。
