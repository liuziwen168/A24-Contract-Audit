## 1. 环境要求

开发环境：Python 3.11+、Node.js 20 LTS、MySQL 8.0+、Docker Engine 24+、Docker Compose v2、Git。Qwen API 需要有效的企业/个人授权，具体模型为qwen3.7-plus，配额为 TBD。赛题不强制实体硬件；演示环境可采用CPU解析和云端模型API，实际资源以压测结果为准。

## 2. 服务、端口与存储

| 服务 | 容器内端口 | 对外暴露 | 说明 |
|---|---:|---:|---|
| nginx | 80/443 | 80/443 | 静态前端、反向代理、TLS终止 |
| frontend | 构建为静态文件 | 否 | 由Nginx提供 |
| backend | 8000 | 否（开发可8000） | 业务REST API |
| ai-service | 8001 | 否 | 仅供backend内部调用 |
| mysql | 3306 | 否（开发可3306） | 业务数据 |

持久化目录规划：`storage/uploads/` 保存原始上传文件，`storage/reports/` 保存HTML/PDF报告，`logs/` 保存应用日志。生产环境上述目录以 Docker volume 挂载并设置最小访问权限；严禁将其提交到Git。

## 3. 环境变量

以下仅为变量名与占位符，不得提交真实密码或API Key：

```dotenv
# frontend
VITE_API_BASE_URL=https://example.com/api/v1
# backend
APP_ENV=development
DATABASE_URL=mysql+pymysql://<DB_USER>:<DB_PASSWORD>@mysql:3306/a24_contract_audit
JWT_SECRET=<JWT_SECRET>
JWT_EXPIRE_SECONDS=3600
AI_SERVICE_BASE_URL=http://ai-service:8001/internal/v1
AI_INTERNAL_TOKEN=<AI_INTERNAL_TOKEN>
UPLOAD_ROOT=/data/uploads
REPORT_ROOT=/data/reports
MAX_UPLOAD_MB=20
# ai-service
QWEN_API_KEY=<QWEN_API_KEY>
QWEN_MODEL=qwen3.7-plus
PROMPT_VERSION=v0.1
INTERNAL_TOKEN=<AI_INTERNAL_TOKEN>
```

`AI_INTERNAL_TOKEN` 与 `INTERNAL_TOKEN` 必须一致且仅存在于部署密钥管理/环境变量中；`QWEN_API_KEY` 不可传递给前端、日志或数据库。

## 4. 本地启动与数据库迁移

推荐顺序：启动 MySQL；配置 backend 与 ai-service 环境变量；执行 Alembic 迁移；启动 AI 服务；启动业务后端；最后启动前端。数据库初始化通过 `alembic upgrade head` 执行，任何结构变更先创建审核过的迁移，再在目标环境执行。初始化演示数据时分别创建普通用户、法务审核员、风控审核员和管理员账号；不同角色使用不同账号，不得用同一普通用户账号完成合同发起和人工审核。禁止手工修改生产表结构，且不得写入真实账号、密码或密钥。

## 5. Docker Compose规划

`docker-compose.yml` 规划 `mysql`、`backend`、`ai-service`、`nginx` 四个服务，前端由构建阶段产物交给 Nginx。backend 与 ai-service 共享只读/受控的上传卷，报告卷仅由 backend 写入；MySQL 不对公网暴露。服务健康检查分别使用 `/health`，MySQL使用原生健康检查；Nginx 仅在依赖健康后接流量。

## 6. 运维检查与常见问题

| 现象 | 检查与处理 |
|---|---|
| 上传后审核失败 | 检查文件格式、共享卷挂载、AI服务健康状态和任务错误码 |
| OCR失败 | 检查图片清晰度、PaddleOCR依赖与语言配置 |
| 大模型超时/限流 | 检查 Qwen 配额、网络和重试日志；不要泄露Key |
| 前端401/403 | 检查JWT过期、反向代理头和用户角色 |
| 数据库迁移失败 | 停止发布，核对当前Alembic版本和备份策略后处理 |

监控指标、生产备份周期、TLS证书来源为 TBD，须在部署验收前确认。上传大小：20MB，超时阈值：默认连接超时 5 秒、读取超时 120 秒、最多重试：2次。
